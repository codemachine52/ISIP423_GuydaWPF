## Ход выполнения

### 1. Рефакторинг кода страницы авторизации (AuthPage)

Для возможности модульного тестирования логина пользователя был проведён рефакторинг:  
- Создан публичный метод `Auth(string login, string password)`, возвращающий `bool` (успешна ли авторизация).  
- В этот метод перенесена вся логика проверки пользователя в базе данных, обработка исключений и вывод сообщений.  
- Обработчик кнопки «Вход» теперь только вызывает `Auth` с параметрами, полученными из полей ввода.
После рефакторинга код страницы стал выглядеть следующим образом (показаны основные фрагменты):

```csharp
 public bool AuthUser(string login, string password)
 {
     if (string.IsNullOrEmpty(login) || string.IsNullOrEmpty(password))
     {
         MessageBox.Show("Введите логин и пароль");
         return false;
     }
     else
     {
         var cl = Core.Context.Client.Where(c => (c.Email == login) && (c.Password == password)).FirstOrDefault();
         if (cl != null)
         {
             Us = cl;
             MessageBox.Show("Вы успешно авторизовались!");
             return true;
         }
         else
         {
             return false;
         }
     }
 }
```

### 2. Создание проекта модульного теста для авторизации

В решение был добавлен новый проект **UnitTestProject** (назван `AuthTests`). Выполнены следующие шаги для подключения тестируемого WPF-приложения:

1. В проекте тестов добавлена ссылка на WPF-проект (через «Добавить ссылку» → «Проекты»).
2. Подключены необходимые сборки: `PresentationCore`, `PresentationFramework`, `WindowsBase` (в разделе «Сборки»).
3. Подключены библиотеки `EntityFramework` и `EntityFramework.SqlServer` (файлы из папки `Bin/Debug` WPF-проекта).
4. В проект тестов скопирован файл `App.config` из WPF-проекта для корректного доступа к строке подключения базы данных.

В тестовом проекте добавлена директива `using` для доступа к страницам, например:

```csharp
using WpfApp1.Pages;
```

### 3. Написание позитивных тестов авторизации (AuthTestSuccess)

Создан тестовый метод `AuthTestSuccess()`, который проверяет успешный вход для всех пользователей, существующих в базе данных. Для этого тест получает список пользователей из таблицы `Client` и для каждого из них вызывает метод `Auth` с правильными логином и паролем.

Пример кода:

```csharp
[TestMethod]
        public void AuthTestSuccess()
        {
            Page2 auth = new Page2();
            Assert.IsTrue(auth.AuthUser("ivanov@mail.ru", "pass123"));
            Assert.IsTrue(auth.AuthUser("petrova@gmail.com", "anna2023"));
            Assert.IsTrue(auth.AuthUser("sidorov@yandex.ru", "alex17"));
            Assert.IsTrue(auth.AuthUser("maria.k@mail.ru", "maria_pass"));
            Assert.IsTrue(auth.AuthUser("den_nik@mail.ru", "den35"));
            Assert.IsTrue(auth.AuthUser("mur123@mail.ru", "cvpasdw"));
            Assert.IsTrue(auth.AuthUser("238947sahd@gmail.com", "AJhsjdshgfi"));
            Assert.IsTrue(auth.AuthUser("alksdj@mail.ru", "QWERTY1"));
            Assert.IsTrue(auth.AuthUser("jkjgjehgxb@mail.ru", "xcvbnm"));
        }

```

После запуска все позитивные тесты были успешно пройдены, так как все пользователи из БД корректно авторизуются.

### 4. Написание негативных тестов авторизации (AuthTestFail)

На основе тестовых сценариев, составленных в практической работе №3, разработан тестовый метод `AuthTestFail()`, который проверяет невозможность входа при различных некорректных данных. Сценарии включают:

- Пустые поля логина и/или пароля.
- Несуществующий логин.
- Неверный пароль для существующего логина.
- Попытка входа пользователя, удалённого из базы данных.

Для проверки последнего сценария был проведён следующий эксперимент (см. скриншоты):

1. В таблице `Client` присутствовал пользователь с `id = 21` (логин `germi4@mail.ru`, пароль `pass45`).

2. Пользователь был удалён из таблицы, изменения сохранены. После обновления базы данных запрос `SELECT * FROM Client` не возвращает запись с `id=21`.

Тест успешно завершился, так как метод `Auth` вернул `false` и показал сообщение об ошибке.

Аналогичные негативные тесты были написаны для всех остальных сценариев. Все они успешно выполняются.

### 5. Создание тестов для регистрации пользователей

По аналогии с авторизацией был проведён рефакторинг страницы регистрации: создан метод `RegisterUser(string email, string pass, string fio, int age, string phone)`, возвращающий `bool` (успешна ли регистрация). В обработчике кнопки «Зарегистрироваться» остался только вызов этого метода с данными из полей.

Затем создан новый проект модульного теста `RegistrationTests` с тестами:

- **Позитивный тест:** проверка регистрации нового пользователя с корректными данными (после теста запись удаляется из БД).
- **Негативные тесты:** проверка на пустые поля, короткий пароль, неверный формат телефона, отрицательный возраст, регистрация существующего пользователя и т.д.

Все тесты успешно пройдены.
